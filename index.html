บอร์ด 3 · Module 01 Analysisหัวใจของระบบ

ชี้ภาพ 3 ภาพ: ต้นฉบับ → U-Net แยกเส้นเลือด → FAZ แล้วชี้กล่อง 3 กล่องด้านบน

หน้า Analysis คือหัวใจของระบบ แพทย์จะเห็น 3 ภาพในหน้าเดียว คือ ภาพต้นฉบับ ภาพที่ U-Net แยกเส้นเลือด และขอบเขต FAZ ที่ระบบวาดทับให้ เพื่อให้แพทย์เห็นว่า AI วัดตรงไหน ไม่ใช่แค่ได้ตัวเลขลอยๆ

ตัวเลขออกมา 3 ระดับครับ ระดับแรกคือค่าจากภาพ Vessel density, Perfusion และพื้นที่ FAZ เป็นตารางมิลลิเมตร ระดับที่สองคือดัชนี Alzheimer 0 ถึง 1 ซึ่งบอกว่า FAZ ต่างจากคนปกติกี่ SD แบ่งเป็น Low, Moderate, High ระดับที่สามคือ% ความเสี่ยงเทียบกับคนวัยเดียวกัน คำนวณด้วยหลักของ Bayes โดยใช้ความชุกของโรคตามอายุเป็นค่าตั้งต้น

บอร์ด 4 · System Architectureสถาปัตยกรรม

ย้ายไปบอร์ด 4 ชี้กล่องจากซ้ายไปขวา

ระบบแบ่งเป็น 4 ชั้นครับ Front-end เขียนด้วย Next.js และ React เป็นหน้าจอ 11 เมนู กราฟและรายงาน Back-end API เขียนด้วย FastAPI ภาษา Python ทำหน้าที่รับภาพ ตรวจสิทธิ์ เรียกโมเดล แล้วส่งผลกลับ AI Model คือ U-Net ที่เราเทรนด้วย PyTorch แล้วแปลงเป็น ONNX ให้รันบน CPU ได้ ไม่ต้องใช้การ์ดจอราคาแพง และ Database เก็บผลวิเคราะห์และ log การใช้งาน

เหตุผลที่แยก Front-end กับ Back-end คนละภาษา เพราะงาน AI ใช้ Python ดีที่สุด ส่วนงานหน้าเว็บใช้ React ดีที่สุด และแต่ละส่วนยังอัปเดตหรือขยายแยกกันได้

บอร์ด 4 · AI Pipeline6 ขั้น

ไล่ 1 → 6 เน้นกล่อง "คุณภาพภาพ ≥ 45%"

เมื่อภาพเข้ามา ระบบทำ 6 ขั้นครับ หนึ่ง รับภาพไม่เกิน 8 MB สอง คัดกรองภาพ ข้อนี้สำคัญมาก ถ้าเป็นรูปถ่ายทั่วไป รูปหน้าคน หรือภาพเบลอ คุณภาพต่ำกว่า 45 ระบบจะปฏิเสธก่อนถึงโมเดล เพราะ AI ที่ได้ภาพขยะก็จะให้ผลขยะ สาม U-Net แยกเส้นเลือดทีละพิกเซล สี่ หา FAZ วัดเป็น mm² ห้า คำนวณความหนาแน่นและดัชนี หก แสดงผลและออกรายงาน

อีกหนึ่งการออกแบบที่เราตั้งใจคือ ถ้าโมเดลทำงานไม่ได้ ระบบจะบอกตรงๆ ว่าวิเคราะห์ไม่ได้ ไม่แอบใช้วิธีอื่นมาแทน เพราะในงานการแพทย์ ตัวเลขผิดอันตรายกว่าไม่มีตัวเลข

บอร์ด 4 · Dataset & Resultsผลทดสอบ

ชี้ตัวเลขทีละกล่อง ช้าๆ

เราทดสอบด้วยชุดข้อมูลสาธารณะ ROSE-1 ที่ผู้เชี่ยวชาญวาดเส้นเลือดไว้ทีละพิกเซล 117 ภาพจาก 39 คน แบ่งเทรน 30 คน ทดสอบ 9 คน แยกรายคนไม่ซ้ำกัน เพื่อให้วัดกับคนที่โมเดลไม่เคยเห็นจริงๆ

ผลคือหาเส้นเลือดได้ Accuracy 87.8% และ AUC 0.908 หา FAZ ซ้อนทับกับผู้เชี่ยวชาญ Dice 0.87 สหสัมพันธ์ r = 0.92 และในแง่ซอฟต์แวร์ เราส่งภาพเดิมซ้ำ 45 ครั้ง ได้ผลเหมือนเดิมทุกครั้ง แปลว่าระบบเชื่อถือได้ ภาพเดิมให้ผลเดิมเสมอ

บอร์ด 4 · สรุปและต่อยอดปิดท้าย

ขอเน้นว่าตัวเลขเหล่านี้คือความแม่นในการหาเส้นเลือดและ FAZ ไม่ใช่การวินิจฉัยโรค Eyezheimer จึงเป็นเครื่องมือคัดกรองก่อนส่งต่อแพทย์

ก้าวต่อไปของเรา คือทดสอบกับผู้ป่วยที่รู้ผลวินิจฉัยจริง เพิ่ม heatmap อธิบายเหตุผลของ AI ลบข้อมูลระบุตัวตนอัตโนมัติ เพิ่มข้อมูลคนไทยจากเครื่องหลายรุ่น และต่อยอดไปคัดกรอง MCI และพาร์กินสัน ขอบคุณครับ พร้อมรับคำถามครับ

ตรรกะที่ควรพูดได้

  • ทุก route เรียก requireConsoleSession() เป็นบรรทัดแรก ไม่มี cookie ที่ถูกต้อง → 401 ทันที
  • ตรวจรหัสเคสด้วย regex ^[A-Z0-9-]{4,64}$ กันการส่งค่าแปลกๆ เข้ามา (เช่น path traversal)
  • ตรวจไฟล์ด้วย magic bytes ไม่เชื่อนามสกุล: PNG ขึ้นต้นด้วย 89 50 4E 47, JPEG ด้วย FF D8 FF, WebP มีคำว่า RIFF…WEBP, TIFF ด้วย II* หรือ MM*
  • ตรวจซ้ำทั้ง 2 ฝั่ง (defense in depth) Next.js ตรวจขั้นแรก Python ตรวจละเอียดอีกรอบ ถ้าฝั่งใดพลาด อีกฝั่งยังกันได้
  • Response ทุกตัวตั้ง Cache-Control: no-store ไม่ให้เบราว์เซอร์/proxy เก็บข้อมูลผู้ป่วยไว้
  • PDF และ DICOM สร้างด้วยโค้ดของเราเอง ไม่ใช้ไลบรารีภายนอก DICOM เขียนเป็นแบบ Secondary Capture, Explicit VR Little Endian ตามมาตรฐาน
  • เก็บข้อมูลโหมดเดโมแบบ atomic write เขียนลงไฟล์ชั่วคราว → fsync → rename ทับ (มี backup) ถ้าไฟดับกลางคันไฟล์เดิมไม่เสีย
  • TypeScript ตรวจชนิดข้อมูลตอนคอมไพล์ และมีสคริปต์ทดสอบ: typecheck, contract-test, modality-test, persistence-test, ui-safety-test, smoke, a11y

AI: U-Net แยกเส้นเลือด และอัลกอริทึมหา FAZ

U-Net คืออะไร

โครงข่ายประสาทเทียมแบบ CNN รูปตัว U ฝั่งซ้าย (encoder) ย่อภาพทีละขั้นเพื่อเข้าใจ "บริบท" ฝั่งขวา (decoder) ขยายกลับเพื่อบอก "ตำแหน่งละเอียด" และมี skip connection ส่งรายละเอียดจากซ้ายข้ามไปขวาโดยตรง เส้นเลือดฝอยเล็กๆ จึงไม่หายระหว่างย่อภาพ ผลคือคำตอบทีละพิกเซลว่าเป็นเส้นเลือดหรือไม่

หัวข้อค่าในโปรเจกต์
งานVessel segmentation (แยกเส้นเลือด) เท่านั้น ไม่ได้จำแนกโรค
เทรนด้วยPyTorch → export เป็น ONNX (ไฟล์ ~7.4 MB)
รันด้วยONNX Runtime บน CPU (CPUExecutionProvider)
Inputtensor [1, 1, 256, 256] float32 ค่า 0–1 (ขาวดำ, bilinear resize, หาร 255)
Outputlogits → sigmoid → threshold 0.5 → mask → ขยายกลับขนาดเดิมแบบ nearest-neighbour
ข้อมูลROSE-1 ชั้น SVC 117 ภาพ / 39 คน · เทรน 30 คน ทดสอบ 9 คน (split ที่ผู้สร้างชุดข้อมูลเผยแพร่)
ผลทดสอบAccuracy 87.8% · AUC 0.908 · Dice 0.70 (model card 0.708)
กันโมเดลถูกสลับตรวจ SHA-256 ของไฟล์ ONNX ให้ตรงกับ model_card.json ไม่ตรง → corrupt ไม่ใช้งาน
ความเร็วcache session ของโมเดลไว้ (lru_cache) ไม่ต้องโหลดใหม่ทุกภาพ

หา FAZ (ใช้อัลกอริทึมภาพ ไม่ใช่ AI)

  1. ย่อเป็นกริด 304×304ภาพครอบคลุม 3×3 มม. → 1 พิกเซล = 3/304 มม.
  2. Box blur 5×5ลด noise ใช้ integral image (cumsum) ให้เร็ว
  3. หาพิกเซลมืดมืดกว่า 0.40 × ค่ามัธยฐาน (median) ของภาพ
  4. หาจุดเริ่มจุดที่มืดที่สุดในวงกลางรัศมี 15% จากศูนย์กลาง
  5. Flood fill 4 ทิศขยายพื้นที่ไปเฉพาะพิกเซลมืดที่ต่อกัน จนขยายไม่ได้อีก
  6. คำนวณพื้นที่จำนวนพิกเซล × (3/304)² mm² · ถ้าได้ < 0.02 หรือ > 1.5 mm² ถือว่าหาไม่เจอ ไม่รายงานดัชนี
  7. วาดเส้นขอบMoore-neighbour tracing → SVG path วาดทับภาพให้แพทย์ดู

พารามิเตอร์จูนจาก 30 ภาพเทรน วัดกับ 9 ภาพทดสอบ: Dice 0.87 · คลาดเฉลี่ย 0.037 mm² · r = 0.92

ค่าอื่นที่รายงาน

  • Vessel density = พิกเซลเส้นเลือด ÷ พิกเซลทั้งหมด × 100
  • Perfusion density = % ของภาพที่สว่างกว่า "ระดับ noise" ของ FAZ (ค่าเฉลี่ย FAZ + 3 SD) เพราะใน FAZ ไม่มีเลือด ความสว่างตรงนั้นคือ noise ของเครื่อง ครอบคลุม 94% ของเส้นเลือดที่ผู้เชี่ยวชาญวาด และติด FAZ ไม่ถึง 2%
  • ค่าเหล่านี้เทียบตรงๆ กับตัวเลขของเครื่อง OCTA ไม่ได้ เพราะวิธีวัดต่างกัน

ดัชนี Alzheimer และ % ความเสี่ยงตามอายุ

ค่าอ้างอิงจากงานวิจัย: FAZ ชั้นผิวของคนปกติ = 0.275 ± 0.10 mm² (O'Bryhim et al., JAMA Ophthalmology 2018) · ผู้ป่วยอัลไซเมอร์มี FAZ ใหญ่กว่าเฉลี่ย 0.54 SD (meta-analysis, Frontiers in Aging Neuroscience 2022)

ขั้น 1  z  = (FAZ − 0.275) / 0.10              จำกัดไว้ −3 ถึง 3
ขั้น 2  LR = exp(0.54·z − 0.54² / 2)            likelihood ratio: กลุ่ม AD เทียบกลุ่มปกติ
ขั้น 3  ดัชนี = LR / (1 + LR)                    prior 50/50 → 0.5 = ไม่บอกอะไร
        Low < 0.35 ≤ Moderate < 0.65 ≤ High
ขั้น 4  odds_ก่อน = p_อายุ / (1 − p_อายุ)          (Bayes)
        odds_หลัง = odds_ก่อน × LR
        risk      = odds_หลัง / (1 + odds_หลัง)

ทำไม LR เป็นสูตรนี้: สมมติค่า z ของคนปกติกระจายแบบ Normal(0, 1) และของผู้ป่วยแบบ Normal(0.54, 1) อัตราส่วนความหนาแน่นของ 2 กราฟระฆังที่จุด z คือ exp(0.54z − 0.54²/2)

จุดอ่อนที่อาจโดนจี้ และวิธีตอบ

"AI ทำนายอัลไซเมอร์ได้แม่นแค่ไหน?"ห้ามตอบ 87.8% (นั่นคือการหาเส้นเลือดระดับพิกเซล) ตอบว่า: "ส่วนที่เป็น AI คือการแยกเส้นเลือด ได้ AUC 0.908 ส่วนความเสี่ยงคำนวณจาก FAZ เทียบค่างานวิจัย เรายังไม่มีข้อมูลผู้ป่วยที่รู้ผลวินิจฉัย จึงยังไม่ได้วัดความแม่นในการทำนายโรค ซึ่งเป็นขั้นต่อไปครับ"
"ทดสอบแค่ 9 คน น้อยไปไหม?"ยอมรับว่าน้อย ROSE เป็นชุดข้อมูลที่ผู้เชี่ยวชาญวาดเส้นเลือดทีละพิกเซล ซึ่งหายาก เราใช้ split มาตรฐานของผู้สร้างชุดข้อมูลและแยกรายคนกันข้อมูลรั่ว แต่ละภาพมีหลายหมื่นพิกเซลให้วัด แต่ต้องเพิ่มข้อมูลแน่นอน
"Accuracy สูงเพราะพื้นหลังเยอะหรือเปล่า?"ใช่ มีผล พื้นหลังมีมากกว่าเส้นเลือด เราจึงรายงาน AUC และ Dice ด้วย ซึ่งไม่หลอกตาเรื่องข้อมูลไม่สมดุล
"ระบบล็อกอินปลอดภัยจริงไหม?"ตอบตรงๆ: ตัวต้นแบบใช้บัญชีเดโมและ session token ที่ตั้งผ่านตัวแปร THERMOEYE_SESSION_TOKEN ซึ่ง cookie เป็น HttpOnly/Secure แล้ว แต่ยังไม่ใช่ระบบผู้ใช้เต็มรูปแบบ ถ้าใช้จริงจะเพิ่มบัญชีแยกรายคน รหัสผ่านแบบ hash (เช่น bcrypt/argon2) และเชื่อมระบบยืนยันตัวตนของโรงพยาบาล
"Database เป็น server memory ปิดเครื่องแล้วข้อมูลหาย?"ใช่ในตัวต้นแบบ (โหมดเดโมเก็บลงไฟล์แบบ atomic ได้) ตั้งใจเพื่อไม่เก็บข้อมูลผู้ป่วยถาวรช่วงทดลอง แผนใช้จริงคือ PostgreSQL + ที่เก็บไฟล์เข้ารหัส
"FAZ ใช้ AI หรือเปล่า?"ไม่ใช้ ใช้อัลกอริทึมภาพ (blur + threshold + flood fill) จูนจาก 30 ภาพเทรน ได้ Dice 0.87 เลือกเพราะอธิบายได้ทุกขั้น และให้ผลเดิม 100%
"ตัวเลข +35–50% / −60–80% มาจากไหน?"เป็นตัวเลขคาดการณ์ (บอร์ดมีดอกจัน) ยังไม่ได้วัดจริงในโรงพยาบาล
ต้องเช็กก่อนขึ้นเวทีถ้าจะเดโมบนเว็บที่ deploy แล้ว ต้องแน่ใจว่า Backend Python ออนไลน์อยู่ (ตั้ง THERMOEYE_LOCAL_INFERENCE_URL ไว้ถูก) ไม่งั้นหน้า Analysis จะขึ้น "AI service could not be reached" · ทางสำรอง: รันเดโมในเครื่องด้วย START-LOCAL-DEMO.bat
